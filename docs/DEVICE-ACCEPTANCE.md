# iPhone 真机验收

本文件是操作步骤，所有空白项默认“未执行”。测试数据只使用随机标记，不录入真实个人任务。不要为了完成更新测试卸载 App。

## 准备

记录实际 iPhone 型号、iOS、Windows、AltServer/AltStore 版本；记录在本地验收表，不提交个人账号、设备序列号或 UDID 到公开仓库。

签名工具从官方来源获取。先检查已有 iTunes、iCloud、Apple 设备驱动，安装前确认路径；不擅自删除已有软件、修改防火墙或重启。Apple 登录、双重验证、信任电脑和开发者模式由用户自行操作。若启用开发者模式要求手机重启，由用户决定并操作。

本步骤采用 [AltServer Windows + AltStore Classic](https://faq.altstore.io/altstore-classic/how-to-install-altstore-windows)，不采用欧盟 AltStore PAL 商店。

下载 Actions 产物，在 Windows 解压产物 ZIP，保留其中两个 `.ipa` 的扩展名。用 PowerShell 的只读命令核对：

```powershell
Get-FileHash -LiteralPath '.\ChainProbe-A-unsigned.ipa', '.\ChainProbe-B-unsigned.ipa' -Algorithm SHA256
```

结果必须与同一产物中的 SHA256SUMS.txt 一致。对照 build-manifest.json、两份 verification.json，确认同一源提交、A/B 标记、不同构建号。

## C04：安装 A

1. 用可传输数据的数据线连接 iPhone，解锁并确认信任电脑。
2. 按官方指引完成 AltServer 和 AltStore 安装、账号认证与开发者模式；免费侧载 App 数量有限，先确认剩余名额。
3. 将 `ChainProbe-A-unsigned.ipa` 通过用户选定的文件传输方式放到 iPhone“文件”中；只有测试 IPA 需要传输。保持 Windows AltServer 可用、设备与电脑连接正常。
4. AltStore Classic → My Apps → `+`，选择 A IPA，等待签名安装。具体按钮以实际版本为准。
5. 打开“链路验证”，确认变体 A、构建号与 verification.json 一致；断开数据线后仍可独立打开。

通过证据：实际构建号、安装工具版本、独立启动结果。下载成功不是安装成功。

## C05：标记持久化

1. 点击“首次创建测试标记”，显示保存成功及 UUID。
2. 用“分享验收摘要”保存到用户控制的位置，记为 A-初始。
3. 在 App 切换器结束该 App，再打开。不得卸载。
4. 核对 UUID 和创建时刻与 A-初始完全一致。

## C06：覆盖更新 A→B

1. 保留 A，使用同一 Apple 账号、相同 AltStore 设置安装 B IPA。
2. 若工具提示会作为另一个 App 安装或要求卸载，停止并记录提示，不用卸载继续。
3. 打开“链路验证”，必须显示变体 B 与 B 的构建号。
4. UUID 和创建时刻仍与 A-初始一致，保存 B-更新后摘要。

只看到新的 B 图标或新 App 启动，不足以证明覆盖更新保留数据。

## C07：手动续签

1. 记录 AltStore 显示的剩余有效时间。
2. 保持 AltServer 和设备连接可用，执行此 App 的 Refresh 或 Refresh All。
3. 记录工具成功状态与刷新后的有效时间。刚安装立即刷新时，显示的天数可能相同，不能凭相同数字宣称延长；保留具体结果。
4. 再次打开 App，构建号不变，UUID 和创建时刻不变。

此测试不代表已经观察完整 7 天周期。完整周期留待后续授权阶段；不要故意等到失效来代替首次续签验证。

## C08：锁屏通知

1. 点击“安排 30 秒后通知”，由用户确认 iOS 通知授权。
2. 确认待处理数量为 1，记录预计触发时间。
3. 立即回到桌面并锁屏，等待约 30 秒。
4. 人工记录实际是否收到“链路验证”横幅/锁屏展示及时间。
5. 返回 App，刷新状态并保存摘要。

专注模式、静音、通知摘要、系统通知设置会影响展示。待处理数量变成 0、通知中心数量为 0 或大于 0，都不能单独证明用户看到了横幅。不要由代理擅自更改这些设置。

## C09：取消通知

1. 安排新一条 30 秒通知，待处理数为 1。
2. 在触发前立即点击取消，核对待处理数为 0。
3. 回桌面并锁屏，等到原触发时间后，确认没有收到这条新的通知。
4. 已送达的旧通知保留在通知中心是正常现象；本 App 不清除通知历史。
